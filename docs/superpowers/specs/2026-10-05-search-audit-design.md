# 检索审计与回答闸门设计

## 目标

将法律检索流程从主要依赖模型自觉执行的文字约定，升级为可观察、可验证的 A+B+C 机制：行为契约、运行状态、程序审计。向量索引同时保存语料哈希，用于识别索引过期。

## 设计

- `SKILL.md` 定义回答状态、核对要求和回答闸门。
- `rank_search.py` 默认输出人类可读审计状态，支持 `--audit-json` 输出机器可读状态，支持 `--strict` 在关键状态不满足时阻止确定性回答。
- 新的哈希模块按稳定顺序计算 `corpus_hash`、`metadata_hash` 和每条条文的 `clause_hashes`。
- `build_vectors.py` 将哈希写入 `vectors.meta.json`；检索时比较当前语料哈希与索引元数据，失配时退回 BM25 并标记索引过期。
- 第一版不做增量向量重建；不改变语料抓取、在线接口和默认检索结果排序。

## 回答闸门

事实不足时状态为 `blocked`，只能追问；向量索引过期时状态为 `conditional`，允许提供候选条文但必须说明使用 BM25 降级；完成事实、检索、哈希和版本核对后才是 `allowed`。

## 哈希输入

条文哈希包含法律全称、条文号、规范化正文、检索层、效力状态、公布日期和施行日期。抓取时间、文件修改时间等不影响哈希。总哈希按检索层、法律名称、条文号和文件路径稳定排序后计算。

## 兼容性

默认模式保留现有命令和文本检索行为；`--audit-json` 与 `--strict` 是新增能力。旧的、没有哈希字段的向量索引视为不可验证并退回 BM25。
