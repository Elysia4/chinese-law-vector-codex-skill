# 更新日志

## 2026-09-28

### 新增：官方文档自动抓取（`scripts/fetch_downloads.py`）

正文来源从"人工在官网点批量下载"改为**脚本自动抓取**，一次 `python scripts/fetch_downloads.py` 即可把官方 docx 抓进 `downloads/`。

- **为什么能做**：实测官网旧的 `/api/*` 接口已下线（POST 返回 405），现行接口在 `/law-search/*` 下：`POST /law-search/search/list` 取清单、`POST /law-search/download/batch`（body 为 `[{"bbbs": "...", "format": "docx"}]`）换取官方 OBS 签名链接，且返回的文件名就是官方的 `<标题>_<YYYYMMDD>.docx`。实测签名链接可直接取回 docx 字节，无需登录与验证码。
- **产物等价**：脚本写出的 zip 与人工"批量下载"导出的 zip 同名同结构，`build_from_downloads.py` 无需改动即可消费，配对仍按（标题 + 公布日期）。
- **可重复运行**：按批落盘 + `downloads/.fetch_state.json` 记录已抓条目，中断后重跑只补缺；整批换链接失败时自动退化为逐条重试并记入失败清单。
- **口径统一**：README、SKILL.md、LICENSE 与脚本注释**全部改口为"由脚本爬取官方公开接口"**，旧表述已清理干净。

对 2473 件官方 docx 逐件做了"源文档 → 产出语料"的覆盖核对，修复了 10 处解析缺陷与 3 项构建稳定性问题，随后重建语料与向量索引。

### 修复：正文丢失

1. **卷首「目录」未剔除**，整段目录被当作正文收录（影响 423 件）。现在按「目录标记 → 目录条目块 → 正文」剥离，编号型目录（「一、管辖」）与「附件一 …」这类非章节条目也能识别。
2. **散文型文件开头整段丢失**。原逻辑"数够 11 段就开正文"，把修改决定、刑法修正案、废止决定的开头段落吃掉（影响 282 件）。例如《刑法修正案（十二）》丢了「一、在刑法第一百六十五条中增加一款…」。现改为按文件头特征判定正文起点。
3. **正文里的文号引用被当成文件头**。正文中「（法释〔2015〕11 号）作如下修改：」这类段落整段被吞（多件司法解释修改决定只剩最后一句）。文号现在要求"整段就是文号"。
4. **「(一) …」开头的正文被当成未闭合的沿革括号**，整篇正文丢弃（实测《保护海底电缆规定》）。沿革行现在要求"括号紧跟日期"。
5. **含序言的文件丢了序言**（宪法、香港/澳门基本法、民族区域自治法、民族团结进步促进法等）。
6. **法典类文件的「第一编/第一章」标题被当成目录吃掉**（民法典、生态环境法典）。
7. **带「目录」的 422 件法规丢了「沿革」与「文号」**，连带影响从正文推定施行日期。
8. **沿革行被排版拆成多段时只取第一段**，沿革与公告日期信息不完整。

### 修复：元数据与分类

9. **官方标题带「（失效）」的 48 件**：标题不再带标记，状态改为「已失效（官方标题标注失效）」并归入 `historical` 层（原先混在决定层/默认层，有被当成现行有效引用的风险）。
10. **`decision` 层 101 件「有关法律问题的决定」被一律标成「修改/废止决定」**，现按类目区分「修改/废止决定」与「时效性未标注」。

### 修复：构建稳定性

- **官方检索接口分页排序不稳定**：同一批数据两次抓取会出现相邻页重叠、个别条目被挤掉——实测连抓 3 次「行政法规」，后两次都丢了 2016 版《麻醉药品和精神药品管理条例》，而行数仍是 833。现在每个类目至少抓两次按（标题+公布日期）取并集，并校验去重后数量；不足会显式告警。
- **官方接口偶发空页**原先被当成"没有更多数据"，改为重试确认。
- **开源汇编索引（GitHub）偶发 SSL 失败会中断整个构建**，改为可降级（老式 `.doc` 退化为"仅元数据"）。
- 补充正文的 HTTP 请求统一走带重试通道，构建可复现。

### 新增

- **施行日期来源标注**：manifest 与文件头新增 `effective_source` 字段（`official` / `text` / `unknown`）。从正文附则推定的日期在文件里带「（正文推定）」标记；合并文本出现"施行早于公布"时会附一行说明。
- **`scripts/pack_skill.py`**：分发打包脚本。实测 7-Zip 写出的 zip 不带 UTF-8 文件名标志位，Windows 资源管理器按系统 ANSI 代码页解码，解压后中文目录名全是乱码、甚至报「文件已存在」（Python/7-Zip 解开却正常，因为它们会猜编码）。该脚本会正确置位并把校验结果打印出来。
- **`build_vectors.py --all-layers`**：默认索引只覆盖现行层（56984 条）；加此参数可把历史版本与修改废止决定一起索引（85853 条、约 35 分钟、约 155 MB）。
- **降级提示更准确**：`--include-repealed` / `--all-layers` 检索时若索引只覆盖现行层，原先提示"索引与语料不匹配，请重建"，容易误导；现在区分「索引只覆盖现行层」与「索引确实过期」两种情况，并给出对应的解决办法。
- **在线兜底检索**（`scripts/search_live.py` + `rank_search.py --live`）：语料没收录、疑似过期、用户质疑时效性时，到官方库实时查条目并给官方链接。**只取元数据，不抓正文**（兜底只做单次一页检索；要完整正文用 `scripts/fetch_downloads.py` 爬取）。本地零命中时会直接给出兜底命令；快照超过 180 天时 `rank_search.py` / `search_corpus.py` 会主动提醒。结果按「匹配度 → 效力位阶 → 标题长度 → 公布日期」排序，问「民营经济促进法」先给国家法律而不是地方实施办法；官方接口整串匹配不上时自动降级为核心短语（去掉「管理办法/暂行条例」这类尾巴）再查一次。
- **数据质量章节**：README 增加逐项核查结果（正文完整性、目录、条文编号、失效分层、字符卫生、可复现性）。
