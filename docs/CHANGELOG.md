## 2026-09-29

### 新增：先问后答的行为契约（SKILL.md「先问后答」一节）

技能从"检索型答题"改成"顾问型问-答"：**默认先判断事实够不够下判断，不够就先问，再作答**。

- **分级**：涉及刑事/行政处罚风险、人身安全、时效临界、金额或期限的情形必须先问清五件事（哪一方、对方做了什么、什么时候、有什么证据、现在到哪一步）；纯知识性提问直接答。
- **红线**：出现"怎么才不留证据""怎么规避执法""怎么把这事弄成合法"这类意图时，不提供任何规避、对抗、隐瞒、伪造的操作指引，只讲清边界、后果与合法补救路径。
- **顾问立场**：回答落到"用户能做什么"——条件式结论 → 法律全称+条款+版本+施行日期 → 用户权利 vs 对方责任（民事/行政/刑事分开） → 时限与材料 → 风险 → 建议咨询执业律师。
- README 增加「使用时的行为约定：先问后答」，`agents/openai.yaml` 的 default_prompt 同步改成顾问口径。

### 抓取层加固：网宿 WAF、自适应限流、清单缓存

跑通全量抓取时连撞几个坑，逐个修掉（`scripts/fetch_corpus.py`、`scripts/fetch_downloads.py`）：

- **WAF cookie 挑战**：flk 前置网宿 WAF，首次请求会 302 回**同一地址**并下发 `wzws_cid`；客户端不存 cookie 就会报 `redirect error that would lead to an infinite loop`（此前误判为本机代理所致，实测跳过代理直连同样复现）。现在 HTTP 层挂进程级共享 cookie 罐。
- **突发限流**：WAF 在请求突发时返回 **HTML 挑战页**，下游表现为 `Expecting value: line 1 column 1 (char 0)`——是 HTML 被当 JSON 解析，不是网络故障；静默数十秒到几分钟即恢复。新增 `AdaptiveLimiter`：被拦间隔 ×2（上限 120s）、连续 4 次被拦进入 5 分钟长冷却、连续 20 次成功才 ×0.8 收紧，间隔持久化到 `downloads/.rate_state.json` 供重跑复用。
- **清单缓存**：官方清单要 80+ 个请求，限流下极贵。现在缓存到 `downloads/.official_checklist.json`（7 天有效，`--refresh-list` 强制刷新）。
- **失败补抓**：主流程结束后按 `--retry-rounds`（默认 2）隔 `--retry-pause`（默认 120s）补抓失败条目；修正 `merge_zip` 未创建父目录导致的崩溃。
- **地方法规**：脚本纳入官方 8 个地方法规类目（共 28419 件），默认不抓，用 `--all` 或 `--groups 地方法规` 打开。

### 修复：配对与覆盖率（58 件错标 + 81 件漏收）

跑通全量抓取并重建语料时，挖出三个一直存在的数据缺陷，全部修掉：

- **官方标题自带「（失效）」后缀**（集中在「有关法律问题的决定」类目），而 `split_name()` 按设计把这个标记从文件名里剥掉 → 两边不一致，**58 件配对失败**，只能以"状态未确认"混进 `current` 层——有被当成现行有效引用的风险。现在两侧统一剥离。
- **官方标题用空格、文件名用「+」**（如「最高人民法院 最高人民检察院…」↔「最高人民法院+最高人民检察院…」）→ 9 件司法解释配不上。新增"忽略空格与顿号"的规范化匹配兜底。

### 新增：第二套 100 题与"无泄漏"改写对照（`eval/queries-v2.jsonl`、`eval/rewrites-v2-main-model.json`）

- **盲写协议**：第二套题由第三方模型生成，先只交付 `id + question`（`eval/queries-v2-blind.jsonl`）→ 主模型据此写改写并落盘 → **写完才拿到答案键**。这样消除了第一套对照里"写改写时已看过答案键"的偏差。
- **结果（无泄漏）**：同一管线，4B 改写 @1 36.0%/@5 82.0%/@8 89.0%；**主模型改写 @1 60.0%/@5 89.0%/@8 94.0%/@10 95.0%**。@1 差距 **+24 点**，说明主模型更擅长把正确条文顶到首位。
- **结论**：**本地生成模型可以从架构里去掉**——改写交给主模型，依赖从 10 GB 降到 0、冷启动从 12 秒降到 0，质量还更高（决策表第 4 项已同步）。
- **答案键验收又抓到 14 处缺陷**：6 处是《反不正当竞争法》用了 2017 旧版条号（现行版是 2025 修订版，条号整体后移）；3 处是该法 2025 年已删除相关条款、答案实际在《电子商务法》《价格法》《招标投标法》；3 处同法内挂错条（物业维修、抵押与租赁、公司名称变更）；2 处补 acceptable。
- **方法论教训**：`条号存在性检查`只能抓"条号不存在"，**抓不到"条号存在但指向别的条文"**（新旧版都有第 6 条而内容不同）——内容核对不能省；出题时应要求模型附带"该条第一句原文"，让错位在生成阶段自曝。

### 新增：隐式加载实测，以及"加载 ≠ 照做"的层次区分

- **用例 `implicit-001`**：不带 `$china-law`、直接问"测评一下我的这个项目是否合法"——用户在新会话实测**隐式加载通过**（触发词是 `description` 里的"是否合法／是否违法"）。
- **`eval/results.md` 明确两个层次**：① 隐式加载（技能有没有被唤起，验法是新会话不提技能名）；② 契约生效（唤起后行为是否照做）。**两者不一定同时成立**，`implicit-001` 验的是①，`safety-00x` 验的是②。
- **一条设计结论**：`description` 的触发词决定隐式加载的边界。"是否合法"能触发；"我破产了我不想活了"这类**倾诉型**表达大概率不能——而这是**有意的**：危机应对属于模型自身的底线，不该外包给技能加载（见 SKILL.md「当事人有自伤倾向时」）。

### 新增：官方文档自动抓取（`scripts/fetch_downloads.py`）

正文来源从"人工在官网点批量下载"改为**脚本自动抓取**，一次 `python scripts/fetch_downloads.py` 即可把官方 docx 抓进 `downloads/`。

- **为什么能做**：实测官网旧的 `/api/*` 接口已下线（POST 返回 405），现行接口在 `/law-search/*` 下：`POST /law-search/search/list` 取清单、`POST /law-search/download/batch`（body 为 `[{"bbbs": "...", "format": "docx"}]`）换取官方 OBS 签名链接，且返回的文件名就是官方的 `<标题>_<YYYYMMDD>.docx`。实测签名链接可直接取回 docx 字节，无需登录与验证码。
- **产物等价**：脚本写出的 zip 与人工"批量下载"导出的 zip 同名同结构，`build_from_downloads.py` 无需改动即可消费，配对仍按（标题 + 公布日期）。
- **可重复运行**：按批落盘 + `downloads/.fetch_state.json` 记录已抓条目，中断后重跑只补缺；整批换链接失败时自动退化为逐条重试并记入失败清单。
- **口径统一**：README、SKILL.md、LICENSE 与脚本注释**全部改口为"由脚本爬取官方公开接口"**，旧表述已清理干净。

对 2473 件官方 docx 逐件做了"源文档 → 产出语料"的覆盖核对，修复了 10 处解析缺陷与 3 项构建稳定性问题，随后重建语料与向量索引。

9. **官方标题带「（失效）」的 48 件**：标题不再带标记，状态改为「已失效（官方标题标注失效）」并归入 `historical` 层（原先混在决定层/默认层，有被当成现行有效引用的风险）。
10. **`decision` 层 101 件「有关法律问题的决定」被一律标成「修改/废止决定」**，现按类目区分「修改/废止决定」与「时效性未标注」。

### 修复：构建稳定性

- **官方检索接口分页排序不稳定**：同一批数据两次抓取会出现相邻页重叠、个别条目被挤掉——实测连抓 3 次「行政法规」，后两次都丢了 2016 版《麻醉药品和精神药品管理条例》，而行数仍是 833。现在每个类目至少抓两次按（标题+公布日期）取并集，并校验去重后数量；不足会显式告警。
- **官方接口偶发空页**原先被当成"没有更多数据"，改为重试确认。
- **开源汇编索引（GitHub）偶发 SSL 失败会中断整个构建**，改为可降级（老式 `.doc` 退化为"仅元数据"）。
- 补充正文的 HTTP 请求统一走带重试通道，构建可复现。

### 新增

- **施行日期来源标注**：manifest 与文件头新增 `effective_source` 字段（`official` / `text` / `unknown`）。从正文附则推定的日期在文件里带「（正文推定）」标记；合并文本出现"施行早于公布"时会附一行说明。
- **`scripts/pack_skill.py`**：分发打包脚本。实测 7-Zip 写出的 zip 不带 UTF-8 文件名标志位，Windows 资源管理器按系统 ANSI 代码页解码，解压后中文目录名全是乱码、甚至报「文件已存在」（Python/7-Zip 解开却正常，因为它们会猜编码）。该脚本会正确置位并把校验结果打印出来。
- **`build_vectors.py --all-layers`**：默认索引只覆盖现行层（56984 条）；加此参数可把历史版本与修改废止决定一起索引（85853 条、约 35 分钟、约 155 MB）。
- **降级提示更准确**：`--include-repealed` / `--all-layers` 检索时若索引只覆盖现行层，原先提示"索引与语料不匹配，请重建"，容易误导；现在区分「索引只覆盖现行层」与「索引确实过期」两种情况，并给出对应的解决办法。
- **在线兜底检索**（`scripts/search_live.py` + `rank_search.py --live`）：语料没收录、疑似过期、用户质疑时效性时，到官方库实时查条目并给官方链接。**只取元数据，不抓正文**（兜底只做单次一页检索；要完整正文用 `scripts/fetch_downloads.py` 爬取）。本地零命中时会直接给出兜底命令；快照超过 180 天时 `rank_search.py` / `search_corpus.py` 会主动提醒。结果按「匹配度 → 效力位阶 → 标题长度 → 公布日期」排序，问「民营经济促进法」先给国家法律而不是地方实施办法；官方接口整串匹配不上时自动降级为核心短语（去掉「管理办法/暂行条例」这类尾巴）再查一次。
- **数据质量章节**：README 增加逐项核查结果（正文完整性、目录、条文编号、失效分层、字符卫生、可复现性）。
