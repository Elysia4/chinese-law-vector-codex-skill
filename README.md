# chinese-law-vector-codex-skill

**中华人民共和国法律法规的离线语料 + 检索技能。** 把 2476 件法律法规（86831 条条文、1156 万字）装到本地，让 Codex 回答法律问题时**先查到条文原文再作答**，而不是依赖模型记忆。BM25 打底，向量语义检索可选，分层过滤防止引用已废止版本。

> ⚠️ **这是一个检索工具，不是法律服务，也不是官方发行物。** 具体事项请以[国家法律法规数据库](https://flk.npc.gov.cn)最新文本为准，重大事项请咨询执业律师。详见文末[免责声明](#免责声明)。

## 30 秒了解

- **开箱即用**：clone 完就能查法条——纯检索**零依赖**（只要 Python 3 标准库，不联网、不需要 API key）
- **向量可选**：想要"换个说法也能搜到"的语义检索，本地跑一条命令生成索引（约 21 分钟，103 MB）
- **为什么不带索引文件**：它由具体嵌入模型生成、与模型绑定，且 103 MB 超过 GitHub 单文件 100 MB 上限 → 详见 [references/vector-index.md](references/vector-index.md)
- **仓库名 ≠ 技能名**：仓库叫 `chinese-law-vector-codex-skill`，技能本身叫 `china-law`。安装时请把文件夹放成 `china-law`（下面有现成命令）

## 为什么需要它

大模型答法律问题最常见、也最危险的错误是**引用已经废止的条文**——中国法律几乎每年都在修订，模型记忆里的版本可能是十年前的。

本项目把法规文本落到本地：回答前必须先在语料里检索到原文，并核对版本与时效性；同时内置防"引错版本"的机制（见[分层检索](#分层检索默认只搜现行有效)）。

## 分层检索：默认只搜现行有效

语料同时收了历史版本（已修改 409 件、已废止 273 件、官方标题标注失效 48 件），因为处理旧案、查法条沿革时用得到。但它**默认不参与检索**：

| 层 | 含义 | 数量 | 默认 |
| --- | --- | --- | --- |
| `current` | 现行有效 + 尚未生效 | 1518 | ✅ |
| `historical` | 已修改 + 已废止 + 官方标注已失效 | 732 | 需 `--include-repealed` |
| `decision` | 修改/废止决定，以及官方未标时效性的决定 | 226 | 需 `--all-layers` |

不分层的话，问"合同怎么解除"会同时命中《民法典》和**已废止的《合同法》**。实测：

```
$ python scripts/rank_search.py 合同解除的条件 --no-vector
1. 《中华人民共和国民法典》第五百六十二条 （民法商法｜现行有效）

$ python scripts/rank_search.py 合同解除的条件 --no-vector --include-repealed
1. ⚠️《中华人民共和国合同法》第九十三条 （民法商法｜已废止）
2. 《中华人民共和国民法典》第五百六十二条 （民法商法｜现行有效）
```

历史版本永远带 ⚠️ 前缀和"已废止/已修改"标签。

## 安装

**方式一：git clone（推荐）**——直接克隆成正确的技能目录名：

```bash
# Windows PowerShell
git clone https://github.com/Elysia4/chinese-law-vector-codex-skill.git "$env:USERPROFILE\.codex\skills\china-law"

# macOS / Linux
git clone https://github.com/Elysia4/chinese-law-vector-codex-skill.git ~/.codex/skills/china-law
```

**方式二：下载 ZIP**——解压后**务必把文件夹重命名为 `china-law`**，再放进 `.codex/skills/`。
（GitHub 的 ZIP 会解压成 `chinese-law-vector-codex-skill-main`，不改名技能无法加载。）

最终路径应为 `<技能目录>/china-law/SKILL.md`。放好后重启 Codex 生效。

## 快速开始

**零依赖**：纯检索只需要 Python 3 标准库——不需要联网、不需要 API key、不需要任何 pip 包。

```bash
cd china-law        # 进入技能目录
python scripts/rank_search.py 公司欠钱不还 股东要不要跟着承担
python scripts/search_corpus.py --law 劳动合同法 --article 47
python scripts/search_corpus.py --stats
```

装好后在 Codex 里直接问法律问题即可，技能会自动生效；也可以输入 `$china-law` 手动调用。

### 使用时的行为约定：先问后答

这个技能的角色是**法律顾问**，不是答题机器。默认行为是**先判断"事实够不够下判断"，不够就先问**，而不是拿到一句话就去检索、直接给结论。

- **涉及刑事/行政处罚风险、人身安全、时效临界、金额或期限**的情形（辞退、工伤、交通事故、欠款、被立案……），先问清五件事——你是谁、对方做了什么、什么时候发生的、有什么证据、现在到哪一步——再给结论。
- **纯知识性提问**（"民法典违约金怎么规定""追诉期多久"）直接回答。
- **不做"怎么不被抓"的助手**：出现"怎么才不留证据""怎么规避执法""怎么把这事弄成合法"这类意图，不给任何规避、对抗、隐瞒、伪造的操作指引，只讲清边界、后果与合法的补救路径。
- 回答落到"你手上有什么牌"：条件式结论 → 法律全称 + 条号 + 版本 + 施行日期 → 你的权利 vs 对方的责任 → 时限与材料 → 风险 → 建议咨询执业律师。

细则见 [SKILL.md](SKILL.md) 的「先问后答」一节。

### 可选：向量语义检索

默认是词面检索（BM25 + 一张人工维护的"口语 → 法条用语"扩展表）。启用向量后，同义改写也能召回：

```bash
ollama pull qwen3-embedding:0.6b                              # 约 639 MB
pip install numpy
python scripts/build_vectors.py --model qwen3-embedding:0.6b  # 约 21 分钟，索引约 103 MB
```

默认只给现行有效层建索引（57309 条）；如果你常查旧案、想连历史版本一起做语义检索，加 `--all-layers`（86831 条、约 35 分钟、约 155 MB）。只覆盖现行层的索引遇到 `--include-repealed` 时会自动退回纯 BM25 并在"检索方式"里说明。

实测对比（同一个问题）：

```
问：公司欠钱股东要不要跟着还

纯 BM25：  《公司法》第二十一条（股东不得滥用股东权利损害公司或其他股东利益）
混合检索： 《公司法》第二十三条（股东滥用法人独立地位逃避债务 → 对债权人承担连带责任）← 正确答案
```

完整说明（显存占用、降级行为、故障排查、参数速查）见 [`references/vector-index.md`](references/vector-index.md)。

## 为什么不内置向量索引

`vectors.npz` **没有**放进仓库，这是刻意的：

1. **超过 GitHub 限制**：约 103 MB，超过 GitHub 单文件 100 MB 硬上限，推送会被直接拒绝；
2. **与模型绑定**：由 `qwen3-embedding:0.6b` 生成（1024 维），换成其他模型则维度或向量空间改变，索引必须整体重建；
3. **本机生成更合理**：一次约 21 分钟，语料不变就不用重建。

`.gitignore` 已排除它，按上一节命令自行生成即可。

## 数据来源与抓取方式

- **元数据**（标题、公布/施行日期、时效性、制定机关、官方链接）取自**国家法律法规数据库**（flk.npc.gov.cn）的公开检索接口。
- **正文**由 `scripts/fetch_downloads.py` **爬取官网公开接口**得到：直接调该站前端自己使用的检索/下载接口，取回的就是官方 docx 与官方文件名（`<标题>_<YYYYMMDD>.docx`）。另有 47 件老式 `.doc` 用开源汇编补齐、16 件仅保留元数据。
- **抓取策略**：按官方清单逐条取，默认每批 50 条换一次签名链接、请求间隔 0.2 秒，断点续抓（`downloads/.fetch_state.json`），抓不到的条目单列出来。
- **文本著作权**：《著作权法》第五条规定，"法律、法规，国家机关的决议、决定、命令和其他具有立法、行政、司法性质的文件"不适用该法。因此法规文本本身不受著作权保护；本项目的目录编排与元数据整理按 MIT 许可提供（见 [LICENSE](LICENSE)）。
- **无隶属关系**：本项目与全国人大常委会办公厅及该数据库运营方无任何隶属、授权或背书关系。

## 更新维护

法规会变。更新流程三步，正文由脚本爬取：

```bash
python scripts/check_updates.py                              # 1) 体检：比对官方清单，报告新增/失效/版本变化
python scripts/fetch_downloads.py                            # 2) 抓取：自动下载官方 docx 到 downloads/（可重复运行，已抓的跳过）
python scripts/build_from_downloads.py                       # 3) 重建语料
python scripts/build_vectors.py --model qwen3-embedding:0.6b #    重建向量索引
```

**注意**：语料变了**必须重建向量索引**——向量按"文件#行号"挂在条文上，行号位移会让旧向量挂到错误的条文。忘了也不会静默出错：检索脚本检测到覆盖率低于 99% 时会自动退回纯 BM25 并提示。

### 忘了更新怎么办：在线兜底

语料是快照。如果没及时更新，技能不会硬答，而是去官方库实时查一次：

```bash
python scripts/search_live.py "民营经济促进法"       # 官方库实时检索：条目 + 时效性 + 官方链接
python scripts/search_live.py "数据安全 条例" --limit 5 --current-only
python scripts/rank_search.py --live 某部新法怎么规定   # 本地零命中时自动兜底
```

触发时机：本地检索零命中、问题涉及语料里没有的规范、用户质疑时效性，或者快照超过 180 天（`rank_search.py` / `search_corpus.py` 会主动提醒）。

**它能给什么**：官方库的条目名、时效性、公布/施行日期、制定机关、官方链接，连本地没收的**地方性法规**也能查到。
**它不给什么**：**正文**。兜底只做单次一页的检索、不取正文——工具会明确引导"最新文本请看官方链接"，而不是凭记忆编条文。（要把正文抓到本地，跑 `python scripts/fetch_downloads.py`。）**部门规章、地方政府规章**也不在这个接口范围内，只能到制定机关官网核实。

兜底只是"别答错"的保险，不是替代品：要离线检索全文，还是按上面三步把语料更新到本地。

## 打包分发给别人

```bash
python scripts/pack_skill.py                       # 生成 china-law-skill-full.zip（约 12 MB，含全部语料）
python scripts/pack_skill.py --with-vectors        # 连向量索引一起打包（约 110 MB，仅建议本机备份）
```

**不要用 7-Zip 或资源管理器直接压缩这个目录。** 中文文件名必须以 UTF-8 写入并置位 zip 的 UTF-8 标志位，实测 7-Zip 默认不置位：Windows 资源管理器会按系统 ANSI 代码页（中文系统即 GBK）解码，解压出来的「宪法相关法」变成乱码目录名，甚至因名字撞车报"文件已存在"——而 zip 本身"看起来"是好的（用 Python 或 7-Zip 解开却正常，因为它们会猜编码）。`pack_skill.py` 会置位该标志并打印校验结果。

对方拿到 zip 后，把 `china-law` 目录放到 `.codex/skills/` 下即可，不需要 clone 仓库。

## 已知限制

- **不是官方发行物**，也不构成法律意见。
- **不含**部门规章、地方性法规、地方政府规章。
- **16 件只有元数据**（老式 `.doc` 且无公开汇编来源，多为年代久远的批复）。
- **133 件的施行日期无法确定**（官方接口该字段为空，正文里也没有"自×年×月×日起施行"）：其中 98 件是无日期的全国人大决定；其余请以官方链接为准。
- **577 件的施行日期是从正文附则推定的**（文件头 `effective_source: "text"`）。经多次修订的合并文本里，附则写的是原文本施行日、官方公布的却是最近一次修订的日期，所以会出现"施行早于公布"，这类文件里都加了提示行说明。
- **快照是静态的**：2026-09-28 之后的新法不在其中，请按上节更新或查官方库。
- 向量检索的可选依赖（Ollama + numpy）需要自行安装。

## 数据质量

语料是对官方 docx 的**本地解析**，公文排版千奇百怪（目录、多段标题、段内换行、附表），因此构建脚本会做结构校验。当前快照在以下几项上做过逐件核查，结论如下：

| 核查项 | 方法 | 结果 |
| --- | --- | --- |
| 正文完整性 | 每个源 docx 中所有 40 字以上的段落必须能在产出里找到 | 2383 件全部命中，0 缺失 |
| 卷首目录 | 检出「目录」段落并剥离，正文不得出现连续 5 行以上标题 | 0 件残留 |
| 条文编号 | 每部实体法应自「第一条」起连续、不重号 | 仅 2 件宪法修正案例外（修正案条号沿用历次修正案的连续编号，从第三十二条/第十八条起，属正常） |
| 失效件分层 | 官方标注失效的件不得留在默认检索层 | 48 件均已归入 `historical` 并加 ⚠️ 提示 |
| 字符卫生 | 不得含零宽字符等不可见字符 | 0 处 |
| 可复现性 | 同一批下载文件连跑两次构建，逐文件比对 MD5 | 2474 个文件完全一致 |

发现解析问题时请连同**原始 docx**一起反馈——修复脚本后重跑 `build_from_downloads.py` 即可，与向量索引无关（索引另建）。
